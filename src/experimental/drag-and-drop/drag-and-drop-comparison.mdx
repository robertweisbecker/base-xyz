# Drag and drop comparison

This is an internal proof of concept for comparing accessible drag-and-drop primitives. It intentionally does not define the production API, export public modules, or choose a winner.

## Dependency Versions

- `@dnd-kit/dom`: `0.5.0`
- `@dnd-kit/helpers`: `0.5.0`
- `@dnd-kit/react`: `0.5.0`
- `react-aria`: `^3.50.0`
- `react-aria-components`: `^1.19.0`

## Official APIs Used

- [React Aria useDrag](https://react-aria.adobe.com/useDrag)
- [React Aria useDrop](https://react-aria.adobe.com/useDrop)
- [React Aria GridList](https://react-aria.adobe.com/GridList)
- [dnd-kit DragDropProvider](https://dndkit.com/react/components/drag-drop-provider/)
- [dnd-kit useDraggable](https://dndkit.com/react/hooks/use-draggable/)
- [dnd-kit useDroppable](https://dndkit.com/react/hooks/use-droppable/)
- [dnd-kit migration guide](https://dndkit.com/react/guides/migration/)

## Shared Features

- Typed task drag data.
- Valid and invalid generic destinations.
- Two-column board movement.
- dnd-kit reordering of Base UI menu-style rows.
- Explicit drag handles with accessible names.
- Visible focus, drag, target, and reset states.
- Local StyleX styling only.

## Comparison Notes

| Concern | React Aria | dnd-kit | Library documented | Locally verified |
|---|---|---|---|---|
| Root ownership | Hooks can operate without an explicit provider | `DragDropProvider` owns the session | Yes | Pending live pass |
| Drag data | Multiple MIME/custom text formats | ID, type, and arbitrary data | Yes | Pending live pass |
| Generic validation | `getDropOperation` returns move/cancel | Droppable `accept` type or predicate | Yes | Pending live pass |
| Generic keyboard navigation | Focuses valid targets with Tab | Moves geometrically with arrow keys | Yes | Pending live pass |
| Collection navigation | Arrow-key drop positions | Geometric keyboard sensor | Yes | Pending live pass |
| Mobile screen readers | Documented double-tap/swipe flow | Not documented as equivalent target navigation | React Aria yes; dnd-kit no equivalent claim | Unverified on physical devices |
| Sort feedback | Drop indicators and commit callbacks | Optimistic/live reflow | Yes | Pending live pass |
| Touch tuning | Browser/library-managed | Configurable delay and tolerance | Yes | Pending live pass |
| Composition | Hook props, component render prop, slots | Refs on arbitrary DOM | Yes | Pending live pass |
| Future native files | Built into React Aria data model | Separate concern | Yes | Not tested in this POC |

Physical iOS VoiceOver and Android TalkBack checks should only be marked verified after testing on real devices. Desktop responsive emulation is not enough evidence for those rows.
